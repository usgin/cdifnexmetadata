# exampleData — the NeXus files the examples are generated from

Five HDF5 files, chosen to span what the extractor actually meets rather
than to flatter it. Each is copied unmodified from a public NeXus example
collection; `exampleMetadata/` holds the CDIF document generated from
each, and `exampleMetadata/generate.py` regenerates them.

| File | Size | Definition | Why it is here |
|------|------|-----------|----------------|
| `FeXAS.nxs` | 2.6M | `NXxas` | 26 `NXentry` groups — the archive-of-parts case. The only example that validates against a full CDIF profile. |
| `APS-USAXS-pinSAXS.hdf5` | 1.9M | `NXsas` | A real beamline file that departs from its own declared definition. |
| `NXsas-autogenerated.hdf5` | 39K | `NXsas` | Generated *from* the definition, so it follows it exactly. The contrast with the file above is the point. |
| `NXmx-Therm_6_2.nxs` | 65K | `NXmx` | Macromolecular crystallography. No crosswalk covers it. |
| `NXtomo-autogenerated.hdf5` | 30K | `NXtomo` | Tomography. Likewise uncovered. |
| `cu_metal_rt.nxs` | 64K | `NXxas` | A clean single-spectrum XAS file — the counterpart to FeXAS's 26-entry archive. |
| `cu_metal_10K.nxs` | 31K | `NXxas` | Declares `NXxas` and is nearly empty. Included because it *fails*. |

## Why the uncovered ones are included

`NXmx-Therm_6_2.nxs` and `NXtomo-autogenerated.hdf5` produce thin
documents: base-class concepts only, no variables, `core` and `discovery`
and nothing more. That is not a defect being hidden — it is what an
unsupported technique looks like, and it is here so the gap can be read
directly instead of inferred from a claim that everything works.

Adding a technique is a crosswalk, not a code change. These two files are
what that sentence costs when nobody has written the crosswalk yet.

## Why a broken file is included

`cu_metal_10K.nxs` declares `NXxas` and then carries almost none of it:
no `NXdata`, no `NXsample`, no scan group, and an `i0` detector with no
`data` in it. It is not corrupt — it reads fine — it is simply thin.

Its document is the only example that **fails** validation, and it fails
for the right reason: the profile requires a detection mode, the file
does not record one, and the extractor says so instead of inventing it.
An examples directory where everything passes tells you nothing about
what happens when something is wrong.

## Provenance

- `FeXAS.nxs` — GSECARS, APS 13-ID-E. Via
  `Cross-Domain-Interoperability-Framework/profile-datastructure`,
  originally
  <https://millenia.cars.aps.anl.gov/nxxas/MultiSpectrumFiles/FeXAS.nxs>.
- `APS-USAXS-pinSAXS.hdf5` — APS 9-ID-C, `APS/NXsas/hdf5/nexus-example.hdf5`
  in the NeXus example data collection.
- `NXsas-autogenerated.hdf5`, `NXtomo-autogenerated.hdf5` — from that
  collection's `autogenerated_examples/nxdl/applications/`, generated
  from the NXDL definitions, so every array is a placeholder scalar.
- `NXmx-Therm_6_2.nxs` — Diamond Light Source i03/i04.

All are unmodified copies. None is licensed by this project; they are
redistributed here as example data on the terms of the collections they
came from.
